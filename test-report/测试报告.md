## 二、缺陷清单（按严重度排序）

### P0 — 企业系统工具类对话链路断裂（核心功能不可用）

- **现象**：点击快捷指令「查公司请假制度」（以及任何触发 OA/HRM/知识库工具的提问），界面出现空白 AI 气泡 +「停止」按钮，卡住约 **69.3 秒** 后，对话中直接展示一段原始 JSON 错误：
  `[错误] Error code: 400 - {"error":{"message":"Invalid JSON data: Failed to deserialize... messages[3]: invalid type: null, expected a string...`。
- **复现路径**：对话页 → 点击「查公司请假制度」→ 等待约 1 分钟。
- **根因（已定位到代码）**：
  1. `agent/app/providers/base.py`：模型流式输出工具调用时，**每个 token 增量被单独 emit 为一个 `tool_calls` 事件**（如 `{"name": null, "arguments": "{"}`），未按 `tool_call` 索引聚合为完整调用；
  2. `agent/app/agents/orchestrator.py`：将每个部分增量当作独立工具调用执行，导致「工具 'None' 未注册」→「oa operation 不能为空」→ 反复重试；
  3. 重试产生的含 `null` 字段消息写入会话历史，回传模型时触发 400；
  4. 前端 SSE 客户端未在错误/超时时复位流式状态，「停止」按钮持续显示。
- **影响**：任何涉及企业系统（OA/HRM/ERP/知识库等）工具的对话都不可用，直接影响核心卖点。
- **建议**：按 `tool_call` 索引聚合增量直到 `finish_reason='tool_calls'` 再执行；前端对工具调用失败给出友好错误并复位流式状态。

### P1-1 工具启停功能实际不可用

- 内置工具（浏览器/代码/数据库/文件系统/Shell/知识库）的「禁用」按钮被 `disabled={tool.source === 'builtin'}` 硬编码禁用（`desktop/src/components/tools/ToolsView.tsx`），**用户无法停用任何内置工具**；
- 连接器工具（BI 等）的「启用」按钮可点，但后端返回 `403 source_not_whitelisted`，且**前端无白名单管理入口**。错误提示存在（页面顶部显示「操作失败：HTTP 403」），但功能闭环缺失。

### P1-2 会话导出功能不存在

- 前端已声明 `api.conversations.export()`（调用 `/api/conversations/{id}/export`），**后端该路由返回 404**（未实现）；UI 也无导出入口。功能为"半成品"。

### P1-3 健康巡检持续误报「连接异常」

- `agent/app/api/ops.py` 引用了**不存在的 `create_provider`**（`from ..providers import create_provider` → ImportError 被 try/except 吞掉），导致运维巡检**每分钟**在审计中写入 `connector_down`（`{'ok': False}`），而实际手动测试连接成功（延迟 2349–5056ms）；
- `/api/ops/health` 的 `checkedAt` 陈旧约 2 小时不刷新，与设置页「● 健康」状态**相互矛盾**。用户看到的健康状态不可信。

### P2（一般）

| 编号 | 问题 | 说明 |
|---|---|---|
| P2-1 | 附件按钮为占位 | 点击仅提示「附件上传功能即将上线」，无实际附件能力 |
| P2-2 | 用量记录 Prompt Token=0 | 用量统计中 prompt_tokens 恒为 0，成本/Token 统计不完整 |
| P2-3 | 模型服务延迟偏高 | 连接测试 2349–5056ms，接近巡检 5s 探测阈值，有误判风险 |

## 四、性能测试

| 指标 | 结果 | 评价 |
|---|---|---|
| 冷启动（进程拉起 → 后端就绪 → UI 可用） | 约 2–4 秒 | 良好 |
| 页签切换渲染延迟 | 11–14ms（对话↔设置双向） | 优秀 |
| 简单问答全量回复 | 11.6s（含模型服务端 2.3–5s 延迟） | 可接受 |
| 故障场景（P0 缺陷） | 卡住 69.3s 后报错 | 严重 |
| 空闲内存占用 | 约 421MB（4 个 Electron 进程） | Electron 常规水平，偏高 |
| 深色/浅色主题切换 | 即时生效，无闪烁 | 优秀 |

**性能小结**：客户端本地渲染性能优秀（切页毫秒级、启动秒级），性能瓶颈全部集中在模型服务端链路（2.3–5.1s 探测延迟）与 P0 缺陷导致的长时间挂起。

## 五、体验评估

**做得好的：**
- 空态设计完整：知识库 / 连接器 / 项目 / 工作流均有引导文案与操作路径；
- 错误反馈机制健全：工具启用失败、技能安装失败、连接测试失败均有明确提示；
- 信息架构清晰：顶部 10 个页签 + 底部工作空间/权限/额度状态栏，导航可达性好；
- 深色模式、权限模式等个性化设置即时生效。

**待改进的：**
- 附件功能占位（P2-1）影响完整对话体验；
- 工具管理页的禁用按钮对用户是"可见但不可用"，易造成困惑（P1-1）；
- 对话错误场景直接将原始 JSON 抛给用户，缺少友好化包装（P0 伴随）；
- 健康状态显示与巡检结果矛盾，会误导用户判断（P1-3）。

## 六、修复建议（按优先级）

1. **P0（发布阻断）**：修复 `providers/base.py` 工具调用流式聚合 + `orchestrator.py` 执行逻辑；前端对工具失败做友好提示并复位流式状态；
2. **P1-1**：内置工具允许停用（或隐藏按钮），连接器工具补充白名单管理入口；
3. **P1-3**：修复 `ops.py` 的错误 import（改用真实存在的 provider 工厂），并刷新 `ops/health` 缓存；
4. **P1-2**：实现后端 `/api/conversations/{id}/export` 或移除前端死代码；
5. **P2**：附件上传落地；用量补记 prompt_tokens；模型探测超时阈值放宽至 10s。
