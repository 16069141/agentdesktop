# 颤翎子AI助手 · 内部分发指南

本指南面向**打包发布者**：把应用打包并分发给团队内的其他成员（Mac + Windows，几十人以上）。

---

## 1. 一次性准备（打包者本机执行）

> 下面的命令只需在「构建发布包的人」的本机执行一次，其他人无需安装任何开发环境。

### 1.1 获取可移植 Python 运行时

本机开发用的 `.venv` 里写死了 `/Users/caojian/...` 路径，**不能**直接拷给其他用户。需要用 `python-build-standalone` 重新构建一份跨机器可移植的解释器。

```bash
# 仅本机（macOS arm64）
bash scripts/fetch-python-runtime.sh macos-arm64

# Intel Mac（macos-x64）
bash scripts/fetch-python-runtime.sh macos-x64

# Windows 构建用的运行时（在 Mac/Linux 上交叉安装，依赖需在 Windows 上冒烟）
bash scripts/fetch-python-runtime.sh win-x64

# 三个一次性全装
bash scripts/fetch-python-runtime.sh
```

产物落在 `runtime/python/<key>/`，整目录可拷贝，含解释器 + site-packages。

### 1.2 生成应用图标

```bash
python3 scripts/make-icons.py
# 产物：desktop/build/{icon.png, icon.icns, icon.ico}（取自颤翎子鹦鹉原 logo）
```

### 1.3 首次发布的最小必装依赖

打包机只需 Node.js（≥ 18）和 Python（≥ 3.11，仅供图标脚本与 fetch 脚本使用）。其余依赖（fastapi / uvicorn / ...）会随运行时一起打进包内。

## 2. 构建发布包

### 2.1 在 macOS 上构建

```bash
# 单平台
bash scripts/build-release.sh mac-arm64     # → release/颤翎子AI助手-0.1.0-arm64.dmg
bash scripts/build-release.sh mac-x64       # → release/颤翎子AI助手-0.1.0-x64.dmg

# 一键出 Mac 两种架构
bash scripts/build-release.sh all
```

### 2.2 Windows 安装包：走 GitHub Actions（唯一可靠路径）

**不要在 macOS 上交叉构建 Windows 包**，实测会撞三道墙：

1. `app-builder` 在 arm64 Mac 上拉不到 Windows 版 Electron 二进制（`ERR_ELECTRON_BUILDER_CANNOT_EXECUTE`）
2. 需要 Wine 跑 rcedit，而 Homebrew 的 `wine-stable` / `wine@devel` cask 已于 2026-09-01 被 Gatekeeper 全部禁用
3. winehq.org 在公司网络被代理拦截（502）

用仓库自带的 workflow 在 `windows-latest` runner 上原生构建：

```bash
# 方式 A：推送 tag（会自动创建 draft Release）
git tag v0.1.0 && git push origin v0.1.0

# 方式 B：Actions 页面手动触发（workflow_dispatch）
gh workflow run build-windows.yml --ref <分支名>   # 仅当 workflow 已在默认分支时可用
```

构建约 **3~4 分钟**，产物在 Actions 运行页的 Artifacts 里（`颤翎子AI助手-windows-x64`），
下载后取出 `颤翎子AI助手-0.1.0-x64.exe`。

本地取回产物：

```bash
gh run download <run-id> --dir release/windows
```

> **关于 Windows 上的 Python 依赖**
> - CI（windows-latest）走**原生安装**：直接用内置 `python.exe -m pip install`，最可靠
> - 在 mac/Linux 上跑 `fetch-python-runtime.sh win-x64` 则是**交叉安装**（`--platform win_amd64`）
> - `uvicorn[standard]` 会拉 `uvloop`，而 uvloop 没有 Windows 轮子 ⇒ 交叉安装时 pip 会
>   `ResolutionImpossible`。脚本已自动改写为 `uvicorn` + `httptools/watchfiles/websockets`
> - 无论哪种方式，**第一个 Windows 包都必须在真机冒烟一次**（确认能启动、能对话）

## 3. 分发产物清单

构建成功后，`release/` 下应有：

| 文件                              | 目标用户                    |
| --------------------------------- | --------------------------- |
| `颤翎子AI助手-0.1.0-arm64.dmg`    | Apple Silicon（M1/M2/...）  |
| `颤翎子AI助手-0.1.0-x64.dmg`      | Intel Mac                   |
| `颤翎子AI助手-0.1.0-x64.exe`      | Windows 10/11 x64           |

实测体积：mac arm64 **173 MB**、mac x64 **160 MB**、Windows x64 **126 MB**
（含 Python 解释器 + 全部依赖 + Electron 运行时）。

**分发通道建议**（任选其一）：

- 内部 GitHub Releases（私有仓库）—— 速度快、版本管理清晰
- 公司 NAS / 文件服务器 —— 适合大团队离线分发
- 钉钉 / 飞书云盘 —— 适合临时推送

## 4. 终端用户安装（把这个章节发给用户即可）

### 4.1 macOS 安装

> ⚠️ 由于没有 Apple Developer 签名，**第一次打开会被 Gatekeeper 拦截**，这是预期行为，请按下面任一方法放行。

**方法 A：解压即用（推荐）**

1. 双击 `.dmg`，把「颤翎子AI助手」拖到「应用程序」文件夹；
2. **不要直接双击 .app**，而是在终端执行（一次性）：
   ```bash
   xattr -cr /Applications/颤翎子AI助手.app
   ```
   或运行分发者提供的辅助脚本：
   ```bash
   bash dequarantine.sh
   ```
3. 现在双击 .app 即可。

**方法 B：手动放行**

1. 在 Finder 里右键点击 .app → 「打开」→ 在弹出对话框中点「打开」；
2. 系统偏好设置 → 隐私与安全性 → 在底部点「仍要打开」。

### 4.2 Windows 安装

> ⚠️ 由于没有 EV 代码签名证书，SmartScreen 会弹窗「Windows 已保护你的电脑」，**不是恶意软件**。

**步骤**：

1. 双击 `颤翎子AI助手-0.1.0-x64.exe`，选择安装路径；
2. 安装完成后在桌面启动；
3. 第一次启动 SmartScreen 弹窗 → 点「更多信息」→「仍要运行」。

### 4.3 首次配置

打开应用后，需要在前端「设置 → 模型服务」中：

1. 至少添加**一个**模型提供商（Base URL、模型名、API Key）；
2. 配置完成后即可对话。

应用的所有数据（对话、附件、设置）都保存在：

- macOS：`~/Library/Application Support/颤翎子AI助手/`
- Windows：`%APPDATA%\颤翎子AI助手\`

**卸载 = 直接删除 .app / .exe + 上面那个目录**。

## 5. 常见问题

| 现象                                                       | 原因 / 解法                                                                        |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| macOS 提示「无法打开，因为无法验证开发者」                  | 执行 `xattr -cr /Applications/颤翎子AI助手.app`                                    |
| macOS 提示「颤翎子AI助手已损坏」                            | 同上（Gatekeeper 拦截「未签名 + 来自网络」的二进制）                                |
| Windows SmartScreen 拦截                                   | 点「更多信息 → 仍要运行」（非恶意软件）                                            |
| App 启动后白屏 / 不响应                                    | 后端在启动；底部状态栏应出现「启动中... → 已就绪」。超过 30 秒仍无变化请删除 userData 目录后再试 |
| 用户改了设置后无效                                          | 检查 `%APPDATA%/颤翎子AI助手/config/settings.json` 是否为只读（早期版本 bug，已修复） |
| 想换 LLM 供应商                                            | 端内「设置 → 模型服务」即可；钥匙串 / keyring 不安全时会明文存 settings.json，需自行清理  |

## 6. 后续维护建议

- **升级**：删除旧 .app，安装新 .app。`userData/` 保留会自动迁移 settings。
- **签名**（可选，未来）：若公司申请了 Apple Developer ID + EV 代码签名证书，更新 `electron-builder.yml` 中的 `identity` 字段即可，**用户将不再需要手动放行**。
- **自动更新**：本指南未包含 electron-updater；如需在客户端实现「检测新版本 → 一键更新」，可在后续接入。
