1核心：模型「说内容」，工具「做文件」

🧠 模型负责（agnes-2.5-flash）

  • 理解文档内容，提炼重点
  • 把内容组织成 Markdown 大纲（# 分页 / - 要点）
  • 决定调用哪个工具、传什么参数
  • 最终用自然语言汇报结果

⚙️ 工具负责（本地引擎）

  • doc_to_html → mammoth 引擎转换 Word
  • generate_ppt → python-pptx 引擎生成幻灯片
  • 真正写出 .html / .pptx 二进制文件
  • 返回文件路径给前端交付

2HTML 转换原理（doc_to_html → mammoth）

📄 Word 内部是什么？

.docx 本质是一个 ZIP 压缩包，里面是 word/document.xml —— 一种叫 WordprocessingML 的 XML 标记语言。标题、表格、列表都以标签形式存在。

🔁 mammoth 做什么？

mammoth 专门做映射转换：把 WordprocessingML 的每个元素翻译成对应的 HTML 标签——w:p→<p>、w:tbl→<table>、w:hyperlink→<a>，同时保留层级结构。

🖼️ 图片怎么处理？

Word 里的图片会从包内提取，转成 base64 内嵌到 HTML（data:image/png;base64,...），所以生成的 HTML 是单文件自包含，拷到哪都能打开。

✨ 为什么"漂亮"？

因为这是忠实还原：Word 原有的标题层级、表格边框、列表缩进都被保留。工具返回原始 HTML 给模型，模型再包一层标题、封面和样式说明，最终由前端打开——不是模型"凭空画"的。

3PPT 生成原理（generate_ppt → python-pptx）

📐 大纲怎么变成页？

模型输出 Markdown 大纲：每个 # 标题 切一页，标题下每个 - 要点 成为该页 bullet。工具按这个规则逐页创建幻灯片。

🗂️ python-pptx 做什么？

它是纯 Python 的 OOXML 写入库，直接操作 .pptx 内部结构（演示文稿 XML）。工具调用 Presentation() 建空白稿，用布局模板往每页写入标题与要点。

🖥️ 版式怎么定的？

固定 16:9 宽屏（13.333 × 7.5 英寸）：第一页封面（标题版式），后续页标题+内容版式；要点超过 120 字自动把字号从 24pt 降到 20pt，防止溢出。

📦 最终产出什么？

一个真实的 .pptx 文件（Microsoft OOXML 格式），可以用 Keynote / PowerPoint / WPS 直接打开编辑——不是截图、不是大纲文本，是真正的演示文稿。

4TXT / 纯文本转换

最简单：文本无需转换引擎，直接以纯文本参与对话。模型读完 .txt 内容后，同样用 generate_ppt（组织大纲生成 PPT）或直接输出 HTML 代码文本。所以 TXT → HTML/PPT 走的也是「模型组织 + 工具渲染」同一条链路。

5为什么比「让模型直接写代码」漂亮？

对比：如果让模型自己输出 HTML/PPT 代码，它只能凭记忆"默写"标签，表格错位、样式缺失、图片丢失是常态。
我们的做法：模型只做它擅长的事（理解 + 提炼 + 编排），文件生成交给专业本地库（mammoth 是专门的 docx 转换器，python-pptx 是专门的操作引擎），它们对文件格式的理解远超语言模型——这就是"漂亮"的本质：分工正确。另外，工具失败（如库缺失、格式错误）会通过 tool_result 带错误信息回填给模型，模型还能自动纠错重试，形成闭环。
