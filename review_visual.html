P0 · 严重 不改会返工/误导开发
① 双 Agent 循环：前端 TS「工具调度」与后端 LangGraph 职责重叠
→ 收敛为后端唯一 Agent 权威
② Provider 两套：前端 TS 与后端 Python 重复，且与「OpenAI 统一协议」矛盾
→ 仅后端一份 OpenAI 兼容层
③ 示例代码有 bug：Ollama 拼全篇向量化 / ChromaDB API 错误 / SSE 粘包 / LangGraph 伪属性
→ 逐条修正并给出可运行示例
④ 版本过时 + 预期乐观：Electron 28 / langgraph 0.0.30；「10-14 周商业化」
→ 更新版本口径，改为 MVP/内测目标
P1 · 重要缺失 影响可用/安全/质量
⑤ 无安全设计：Shell「沙箱」无落地、API Key 明文、MCP 不可信
→ 新增安全章节（钥匙串/白名单/审计）
⑥ 无上下文治理：长对话会爆 token 预算
→ 预算 + 滑动窗口 + 摘要压缩
⑦ 无模型路由/降级：任务与模型不匹配、故障无兜底
→ 任务路由表 + fallback 链
⑧ RAG 检索单薄：中文 Embedding 选型、无混合检索/重排/引用溯源
→ bge-m3 + BM25 融合 + rerank
⑨ 无通信协议定义：SSE 事件与 API 无 schema，无法并行开发
→ 新增 §5 协议表
⑩ 无测试/评测：AI 应用缺 eval 基线易「修好一个、回归一片」
→ Golden set + 回归门禁
⑪ Electron↔Python 生命周期缺失：子进程启停/崩溃重启/打包未设计
→ 主进程管理 + PyInstaller 打包
P2 · 建议 完善度/体验
⑫ 无产品定位/需求：缺目标用户、场景、MVP 边界、竞品差距
→ 新增 §1 定位与范围
⑬ 无验收标准：各阶段「完成」无法判定
→ §1.3 验收清单 + 里程碑门禁
⑭ 路线图重复：Phase1「模型切换」与 Phase2「Provider 切换」重复
→ 合并去重，补安全/测试任务
⑮ 无可观测性：无日志、用量统计、成本核算
→ 新增 §12 用量与日志
⑯ 缺辅助能力：系统提示词管理、会话导出、边界声明
→ 目录与接口中补齐
优先级按「对开发正确性与交付风险的影响」划分：P0 需在开工前修正，P1 建议在 MVP 内补齐，P2 可迭代期完善。全部 16 项已在本轮修订版中处理。
